# ADR-0009. Генератор головоломок: копание с проверкой единственности и калибровка по потолку техник

- **Статус:** Принято
- **Дата:** 2026-11-14
- **Связано с:** [ADR-0003](0003-difficulty-rating.md) (оценка сложности),
  [ADR-0008](0008-sudoku-solver-algorithm.md) (решатель),
  [ADR-0002](0002-project-and-layer-structure.md) (слои)

## Контекст

Требования [REQUIREMENTS.md](../REQUIREMENTS.md):

| ID | Требование |
|---|---|
| FR-02 | Ровно три режима сложности: Easy, Normal, Hard |
| FR-04 | Генерация детерминирована: одинаковый `seed` → одинаковая головоломка |
| FR-05 | Каждая головоломка снабжена оценкой сложности, попадающей в диапазон своей категории |
| FR-06 | Категории сложности не пересекаются |
| FR-11 | Каждая головоломка имеет единственное решение |
| NFR-05 | Время генерации ≤ 1 с (Easy/Normal) и ≤ 5 с (Hard) |

Ключевая проблема — **как честно классифицировать головоломку**. Исследование
([ADR-0003](0003-difficulty-rating.md)) показало, что число подсказок — слабый признак
сложности (корреляция с человеческой сложностью ≈ 0.25), а устойчивая воспроизводимая
метрика — **потолок логических приёмов** (technique ceiling): минимальный уровень
приёмов, при котором головоломка решается полностью, без перебора.

Дополнительные требования к генератору:

1. Единственность решения проверяется **фактически**, а не предполагается.
2. Головоломка не может быть помечена уровнем, который не подтверждён проверкой.
3. Разные `seed` дают разные головоломки (разнообразие).
4. Генерация не должна «имитировать» сложность: случайно удалённые клетки сами по себе
   не делают головоломку сложной.

## Решение

### 1. Метрика сложности — потолок приёмов (лестница v1)

Лестница приёмов (порядок зафиксирован в [ADR-0003](0003-difficulty-rating.md)):

| Уровень | Приём | Реализация |
|---|---|---|
| 1 | naked single | `LogicalSolver.ApplyNakedSingles` |
| 2 | hidden single | `LogicalSolver.ApplyHiddenSingles` |
| 3 | pointing pair | `LogicalSolver.ApplyPointingPairs` |
| 4 | claiming pair | `LogicalSolver.ApplyClaimingPairs` |
| 5 | naked pair | `LogicalSolver.ApplyNakedPairs` |
| 6 | hidden pair | `LogicalSolver.ApplyHiddenPairs` |

**Потолок** головоломки — минимальный уровень `L`, при котором решатель решает её
полностью. Важно: это не «самая сложная применённая техника», а минимальный
*достаточный* уровень. Так определение устойчиво к порядку применения приёмов и
проверяемо: тест `LogicalSolverTests.Technique_ceiling_is_minimal_level_that_solves_the_puzzle`
требует, чтобы на уровне `L − 1` решение не находилось, а на уровне `L` — находилось
и совпадало с истинным решением.

Все приёмы — **корректные** (не эвристические): они не могут привести к неверному
значению, поэтому любое найденное заполнение является решением. Это проверяется тестом
`LogicalSolverTests.Logical_solution_always_equals_the_true_solution` на 45 сгенерированных
головоломках всех трёх уровней.

### 2. Калибровка полос

Полосы уровней описаны в одном месте — `DifficultyBands`, — чтобы «заявленный уровень»
и «проверенный уровень» не могли разойтись:

| Уровень | Потолок приёмов | Страховочный минимум подсказок |
|---|---|---|
| Easy | 1–2 (одиночные приёмы) | 22 |
| Normal | 3–4 (указывающие и заявляющие пары) | 20 |
| Hard | 5–6 (голые и скрытые пары) | 20 |

Полосы не пересекаются и покрывают всю лестницу v1 — это обеспечивает FR-06.

Минимум подсказок — **страховка, а не критерий сложности**: он не позволяет выдать
аномально пустую доску, но сам по себе уровень не определяет. По эмпирике он почти
не срабатывает: естественная остановка копания наступает раньше (см. измерения ниже).

### 3. Алгоритм генерации

`PuzzleGenerator.Generate(difficulty, seed)`:

1. **Заполнение.** `RandomGridFiller` строит случайное корректное решение: выбор ячейки
   по правилу минимального числа кандидатов (MRV), порядок цифр перемешан seed-генератором.
2. **Симметрия.** Решение преобразуется случайной перестановкой цифр, строк внутри блоков,
   столбцов внутри блоков и блоков между собой. Все преобразования сохраняют корректность
   судоку и повышают разнообразие при одинаковом seed.
3. **Копание.** Заданные значения удаляются в случайном порядке. После каждого удаления
   проверяются два условия:
   - **единственность**: `ISudokuSolver.CountSolutions(candidate, 2) == 1`;
   - **решаемость без перебора**: `IDifficultyRater.CanSolveWith(candidate, band.MaxTechniqueLevel)`.
     Если хотя бы одно условие нарушено, удаление откатывается.
4. **Полоса.** Пока доска не «вошла» в полосу (потолок ниже `band.MinTechniqueLevel`),
     запоминается последняя доска, подтверждённая как принадлежащая полосе.
5. **Приёмка.** Итоговая оценка пересчитывается оценщиком (`LogicalDifficultyRater.Rate`)
   по **независимому** пути: решатель заново считает решения (проверка единственности) и
   заново определяет потолок. Головоломка принимается, только если
   `DifficultyBands.Contains(rating, band)` — то есть единственность подтверждена,
   перебор не требуется и потолок попадает в полосу. Если итоговая доска вышла из полосы,
   берётся запомненная доска из шага 4; если и она не подходит — попытка считается
   неудачной.
6. **Повтор.** До 100 попыток (`PuzzleGenerator.MaxAttempts`); затем
   `PuzzleGenerationException`. Каждая попытка использует новое решение и новый порядок
   копания из того же seed-потока.

Головоломка, у которой нет ровно одного решения, **не может быть возвращена**: это
проверяется на каждом шаге копания и ещё раз при приёмке.

### 4. Детерминизм и разнообразие

- Случайность берётся только из `IRandomSource` (`SystemRandomSource` поверх `System.Random`
  с явным seed). `Random.Shared` и `DateTime.Now` не используются.
- Один и тот же seed и уровень → побайтово одна и та же головоломка (тест
  `Generate_is_reproducible_for_the_same_seed`).
- Разные seed → разные головоломки: на выборке из 300 головоломок на уровень
  совпали 0 решений (300 различных наборов подсказок и 300 различных решений).

### 5. Измерения

Условия: .NET 10.0.14, macOS (arm64), сборка Release, 300 головоломок на уровень
(всего 900), seed = 1…300.

| Уровень | Ошибок генерации | Не единственные | Не в полосе | Различных головоломок | p50 | p95 | max |
|---|---|---|---|---|---|---|---|
| Easy | 0 | 0 | 0 | 300/300 | 1.5 мс | 6.4 мс | 17.2 мс |
| Normal | 0 | 0 | 0 | 300/300 | 14.1 мс | 58.4 мс | 147.2 мс |
| Hard | 0 | 0 | 0 | 300/300 | 16.3 мс | 69.4 мс | 148.1 мс |

Распределение потолков и числа подсказок:

| Уровень | Потолки | Подсказки (min / p50 / max) |
|---|---|---|
| Easy | 1 — 7 головоломок, 2 — 293 | 22 / 25 / 28 |
| Normal | 3 — 229, 4 — 71 | 22 / 25 / 29 |
| Hard | 5 — 220, 6 — 80 | 22 / 25 / 28 |

Запас по NFR-05: Easy/Normal — двукратный (p95 ≈ 6 % бюджета), Hard — тридцатикратный
(p95 ≈ 1.4 % бюджета). Ограничение применимо к этой машине: при более медленном CPU
или при переходе на лестницу v2 (X-Wing, цепочки) время вырастет — оценщик v2
должен быть измерен отдельно.

Дополнительно прогнана выборка из 1002 головоломок (`SUDOKU_FULL_BATCH=1`): все головоломки
имеют ровно одно решение и попадают в заявленную полосу.

### 6. Что входит в объём этапа, а что — нет

Входит: генерация, рейтинг v1, калибровка полос, детерминизм, тесты.

Не входит (этап 5, [ADR-0003](0003-difficulty-rating.md)): приёмы уровня v2
(X-Wing, Swordfish, XY-Wing, цепочки), подсказки с объяснением, предгенерированный банк
головоломок. Поэтому «Hard» в v1 означает «требует приёмов исключения пар», а не
«требует X-Wing».

## Последствия

**Положительные**

- Классификация головоломки проверяема и воспроизводима: один и тот же seed даёт одну и ту же
  головоломку с одной и той же оценкой.
- Единственность решения подтверждается фактически, а не предполагается; решатель не может
  ошибиться «по построению».
- Разнообразие обеспечено тремя независимыми механизмами (случайное заполнение, симметрия,
  случайный порядок копания).
- Время генерации укладывается в NFR-05 с большим запасом; генерацию можно выполнять
  в фоновом потоке (этап 9) без индикатора загрузки.

**Отрицательные**

- Границы между уровнями отражают порядок лестницы v1, а не человеческую сложность:
  hidden pair в некоторых источниках считается не сложнее naked pair. Порядок зафиксирован
  в [ADR-0003](0003-difficulty-rating.md) и является осознанным упрощением.
- Число подсказок у всех трёх уровней пересекается (22–29): уровни различаются техниками,
  а не размером. Это следствие отказа от метрики «число подсказок».
- Калибровка «нормальности» и «сложности» не подтверждена живыми игроками — она проверяется
  только согласованностью «потолок ↔ полоса».
- Генерация `Hard` детерминирована по seed, но зависит от версии `.NET`: алгоритм
  `System.Random` может измениться между версиями среды. Сохранённые головоломки
  хранятся вместе с оценкой, поэтому смена версии не ломает уже выданные головоломки.

## Альтернативы

| Вариант | Оценка |
|---|---|
| Классификация только по числу пустых клеток | Отклонён: корреляция ≈ 0.25, Easy и Hard неразличимы (ADR-0003) |
| Оценка по времени решения машинного решателя | Отклонён: зависит от порядка перебора, разброс от 0.02 с до 190 с |
| Генерация «слепым» удалением до упора + оценка результата | Отклонён: доля попаданий в полосу мала, время нестабильно; вариант с ограничением полосы даёт 100 % попаданий |
| Генерация по заданной технике (как в tdoku) | Отложен: требует лестницы v2; в v1 эквивалентно ограничению по верхней границе полосы |
| Предгенерированный банк головоломок | Отложен (этап 5/12): ADR-0003, лицензия CC BY-NC-SA у банка Project Euler |
