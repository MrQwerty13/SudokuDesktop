# ADR-0004. Сохранение состояния и таймер

- **Статус:** Принято
- **Дата:** 2026-11-13
- **Связано с:** [ADR-0002](0002-project-and-layer-structure.md)

## Контекст

Требования: прогресс переживает перезапуск приложения (FR-31…FR-35), приложение полностью
офлайн, таймер Time Attack должен быть точным (NFR-07: ошибка ≤ 1 с за заход), а тесты
не должны зависеть от реального времени (AGENTS.md, §5).

Дополнительно: таймер не должен «отставать», когда UI-поток занят (генерация головоломки,
перерисовка) или приложение свёрнуто.

## Решение

### 1. Где живут данные

| Что | Где | Как |
|---|---|---|
| Текущий заход | `%LOCALAPPDATA%/Sudoku` (Windows), `~/Library/Application Support/Sudoku` (macOS), `~/.local/share/Sudoku` (Linux) | `SpecialFolder.LocalApplicationData` — единый кроссплатформенный путь |
| Настройки | тот же каталог, отдельный файл | `settings.json` |
| Статистика (будущее) | тот же каталог | `statistics.json` |

Имена файлов: `state.json` (текущий заход), `settings.json`.

Формат: JSON (`System.Text.Json`), версия схемы в поле `version`.
Домен не зависит от JSON: сериализуемые DTO и маппинг живут в `Sudoku.Infrastructure`.

### 2. Атомарность записи

1. Сериализация в память.
2. Запись во временный файл `state.json.tmp` в том же каталоге.
3. `File.Move(tmp, path, overwrite: true)` — атомарная замена на всех трёх ОС
   (`rename(2)` / `MoveFileEx`).

Результат: файл сохранения не может оказаться «наполовину записанным» при сбое питания
или kill процесса.

### 3. Устойчивость к повреждению

При чтении:
- файл отсутствует → старт с чистого состояния;
- JSON невалиден или `version` неизвестна → лог предупреждения + старт с чистого состояния
  (приложение **не падает**);
- повреждённый файл переименовывается в `state.json.corrupt-<timestamp>` (диагностика).

### 4. Таймер

**Измерение интервала** — через монотонный источник, а не через счёт тиков:

- `ITimeProvider` в `Sudoku.Core` с двумя членами: `DateTimeOffset UtcNow` и
  `TimeSpan Elapsed` (монотонный). Реализация по умолчанию — `SystemTimeProvider`
  (`DateTimeOffset.UtcNow` + `Stopwatch`).
- Логика считает **остаток = limit − elapsed**, где `elapsed` — разница между
  сохранённым моментом старта и текущим моментом. Это устойчиво к пропуску тиков,
  перерисовкам и уходу приложения в фон.
- **Отображение** обновляется через `DispatcherTimer` (интервал 200 мс) — он отвечает
  только за перерисовку текста, но не за источник истины.

**Время в фоне:** таймер продолжает идти (по умолчанию). Пауза — только по явному
действию пользователя (вопрос владельцу Q-03/Q-04; см. `docs/REQUIREMENTS.md`).

**Сохранение:** при выходе, по истечении времени и раз в N секунд (кроме режима Endless —
там достаточно сохранять при выходе и после каждой головоломки).

### 5. Детерминированные тесты

`ITimeProvider` подменяется в тестах на управляемый `FakeTimeProvider` (ручной сдвиг времени).
Тесты таймера проверяют: лимиты 600/1200/1800 с, момент перехода в состояние «время вышло»,
поведение при переходе через границу минуты и корректность расчёта при пропуске тиков.

## Последствия

**Положительные**
- Никаких сетевых и внешних зависимостей; полный офлайн.
- Атомарная запись снимает целый класс жалоб «после перезапуска всё пропало».
- Таймер устойчив к зависаниям UI и к уходу в фон.
- Тесты таймера и хранилища детерминированы и не зависят от реального времени.

**Отрицательные**
- Нет синхронизации между несколькими запущенными экземплярами приложения: два процесса
  будут перезаписывать `state.json` друг друга. Решение — «последний выигрывает»
  (last-writer-wins) либо запрет второго экземпляра (вопрос владельцу Q-13).
- JSON — не самый компактный формат; при большом числе головоломок в записи он раздувается.
  Для захода из 1–3 головоломок это несущественно.
- Перезапись файла при каждом автосохранении создаёт небольшой износ; для одиночной игры
  это нерелевантно.

## Альтернативы

| Вариант | Оценка |
|---|---|
| **SQLite** | Отклонён: избыточен для одной записи; добавляет нативную зависимость |
| **Protobuf / MessagePack** | Отклонён: нет читаемости, сложнее отладка, выигрыш в размере не нужен |
| **`DispatcherTimer.Tick` как источник времени** | Отклонён: теряются тики при зависании UI, не работает в фоне |
| **`DateTime.Now` без монотонности** | Отклонён: не устойчив к переводу часов и к DST |
| **Автосохранение после каждого ввода** | Отклонён: лишний износ I/O; достаточно автосохранения раз в ~10 с и на ключевых событиях |
| **Хранить состояние в реестре/настройках ОС** | Отклонён: разные API на каждой ОС, ограничения на размер и формат |
